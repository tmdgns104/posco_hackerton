# SteelTrust × SlagWatch
## 공개 철강 주조 진동 AI의 실패 조건 자동 탐색과 판단 보류

원본을 맞힌 분류기가 같은 진동 구간에 합성 교란을 주면 오판하는 조건을 찾고, 그 오판을 게이트가 전달했는지 보류했는지 기록한다. 기존 ZIP의 세 모델과 네 fold 묶음을 재사용한다. 신규 모델 학습은 필요하지 않다.

### 실행
Windows용 Python 3.11 64비트와 Python Launcher를 설치한 뒤, 압축 전체를 풀고 START_WINDOWS.cmd를 더블클릭한다. 처음 패키지를 설치할 때 인터넷이 필요하다. 서버는 127.0.0.1에서 열리고 준비가 끝나면 로컬에서 오프라인으로 실행한다. 검증은 Linux/Python 3.11.17에서 수행했다. Windows OS 직접 실행은 후속 현장 확인 항목이다. 기존 3.12 환경도 사용할 수 있다.

수동 실행 명령 (프로젝트 폴더, 가상환경의 Python)

    python -m pip install -r requirements.lock.txt
    python -m streamlit run app.py
    python -m unittest discover -s tests -v

배치 평가를 다시 만들 때 아래 순서로 실행한다.

    python -m src.search --max-trials 2000 --max-seconds 90
    python -m src.metrics_gate

CLI는 이번 확장의 search_results.csv, preexisting_errors.csv, gate_metrics.json, gate_by_group.csv, run_manifest.json을 기록한다. UI 버튼은 현재 세션에서 새로 탐색하고 CSV를 내려받을 수 있다. 예전 예측/지표는 predictions.csv 및 metrics.json에 보존했다. src/train_eval.py는 v2가 fold 모델을 생성한 경로다.

### 직접 써보기
1. 실행하면 ‘자동 실패 탐색’에서 저장된 2,000회 탐색이 열린다. ‘실패 조건 자동 탐색’을 눌러 기본 400회를 새로 실행한다. ‘탐색 설정’에서 시험 모델, 목표 오류, 교란 종류, 횟수를 바꿀 수 있다.
2. ‘오판 보류’와 ‘오판 전달’을 차례로 선택한다. 사례를 선택할 때마다 같은 입력·모델·파라미터로 처음부터 재실행한다. 원본/교란 파형, 점수와 판정 차이, 게이트 사유를 확인한다. 스파이크 시험은 표식이 주입 위치다.
3. ‘선택 사례 JSON’으로 재현 정보를 저장한다. ‘신뢰성 게이트’에서 정책을 비교한다. 이 탭은 발견된 사례의 부분집합 대신 각 고정 시나리오의 전체 480구간을 사용한다.

### 실험 결과
주 시험 모델은 진폭 RF, 정책 G2의 기본 마진은 0.10이다. 원본을 맞힌 슬래그 구간 20개와 비슬래그 구간 20개에 결정적 순서의 그리드를 적용했다. 사용한 seed는 42, 43이다. 2,000회 중 33개 창에서 415개 조건이 오판으로 바뀌었다. 오경보 266개, 미검출 149개였다. 225개를 보류했고 190개는 그대로 전달했다. 같은 40개 창에서 여러 교란을 반복한 시험이므로 독립 사건 수나 현장 발생률로 읽을 수 없다. 기존부터 오판한 228개 원본 창을 별도 기록했다.

| 원본 진폭 RF · 480구간 | 모델 단독 G0 | 입력 검사 G1 | 입력 검사 + 점수 마진 G2 |
|---|---:|---:|---:|
| 오판 전달 (전체 입력 기준) | 228/480 | 228/480 | 98/480 |
| 오판 보류 (모델 오판 기준) | 0/228 | 0/228 | 130/228 |
| 정답 보류 (모델 정답 기준) | 0/252 | 0/252 | 97/252 |
| 자동 전달 | 480/480 | 480/480 | 253/480 |
| 통과 판단 중 오류 | 228/480 | 228/480 | 98/253 |

고정 X축 스파이크에서 G2는 잘못 전달하는 건수를 234건에서 105건으로 줄였지만, 전달된 판단만 보면 오류율이 48.75%에서 54.12%로 올랐다. 정상 판단 157건도 보류하기 때문이다. 특정 환경에서 이 정책이 안전성이나 실질 검토 효율을 개선했다는 결론은 낼 수 없다. 두 정책을 비교할 때 자동 전달률, 조건부 오류율, 정답 보류를 함께 확인해야 한다.

### 단계별 변경·검증

| 단계 | 변경 또는 확인 | 근거 |
|---|---|---|
| v2 감사 | CSV 48개, 16그룹, 480구간, fold 4개, 세 모델 및 기존 테스트 확인 | tests/test_contracts.py, artifacts/, reports/manifest.csv |
| 교란·탐색 | src/faults.py의 파라미터 함수와 src/search.py. 누락/고정은 기존 기능 시험으로 유지 | 모든 시도, SHA256, 스파이크 위치·부호, 원본/교란 점수를 CSV에 기록 |
| 신뢰성 게이트 | src/inference.py의 입력 검사·추론 함수를 공용화, src/gate.py에 G0/G1/G2/G3 | 미정의 크기, NaN/Inf, 고정축에서 추론을 호출하지 않는다 |
| 평가 | src/metrics_gate.py가 전체 OOF 예측에서 분모와 그룹별 지표 산출 | gate_metrics.json, gate_by_group.csv |
| UI | 기존 구간 검사·모델 평가 탭 유지, src/steel_ui.py에 탐색·재현·정책 평가 추가 | 새 탐색, 저장 결과 전환, 사례 재현·내보내기 |
| 실행 확인 | tests/test_steel.py 및 기존 테스트. 브라우저에서 라이브 탐색과 결과 표시 확인 | Linux · Python 3.11 |

G0에서 품질 실패 입력은 NO_PREDICTION으로 집계한다. G1 이상은 입력 이상 보류로 집계한다. 두 경우 모두 모델 점수·예측이 없으므로 모델 오판 차단율의 분모에서 제외한다. G2의 0.40과 0.60 경계는 통과한다. G3는 같은 fold의 두 RF 간 클래스 불일치도 보류한다. 마진 민감도 분석은 사전에 정한 다섯 값을 기존 OOF 결과에서 비교한 기술 통계다. 실제 안전 인증 또는 독립적인 최종 성능 측정에는 별도 데이터가 필요하다.

### 3분 시연 진행
- 0:00–0:30. 현장 문제와 공개 SSFD 자료를 소개한다. 실제 주조 기록에 표시된 상태 라벨을 사용한다. CNN-LSTM 선행연구와 달리 이번 시험 대상은 기존 경량 RF다.
- 0:30–1:00. 구간 검사에서 한 기록의 정답·점수·학습 제외 그룹을 확인한 뒤 자동 탐색으로 이동한다.
- 1:00–1:50. 목표와 예산을 선택해 실제 탐색을 실행한다. 저장 결과로 돌아와 유발된 오경보·미검출과 원본부터 틀린 사례의 차이를 설명한다.
- 1:50–2:30. 보류된 오류와 통과한 오류 하나씩을 선택한다. 같은 입력·교란·모델로 점수를 재현하고, 게이트가 정답도 보류하는 사례를 보여준다.
- 2:30–3:00. 전체 480개 원본과 스파이크 조건의 결과를 비교한다. 어떤 정책이 검토 부담과 전달 오류를 어떻게 바꾸는지 설명한다.
