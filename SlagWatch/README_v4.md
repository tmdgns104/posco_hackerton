# SteelTrust × SlagWatch v4

**공정 AI 검증 엔지니어가 찾아낸 실패를 회귀 시험으로 남기고, 수정 후 실제로 고친 오류와 새로 만든 오류를 같은 데이터에서 비교하는 로컬 앱.**

슬래그 RF는 시험 대상이다. SteelTrust는 실측 신호의 복사본에 교란을 주고 실패를 찾아 재현한다. v4는 그 실패를 서로 다른 수정 방식으로 다시 시험한다. 원본·교란 양쪽에서 분류 능력을 보고, 게이트는 같은 자동 처리량에서 따로 평가한다. 공개 주조 기록을 사용하는 오프라인 개념증명이다.

## 실행

Windows에서 ZIP 전체를 풀고 Python 3.11 64비트와 py 런처가 있는 상태에서 **START_WINDOWS.cmd**를 실행한다. 최초 패키지 설치에는 인터넷이 필요하다. 이미 생성된 모델과 평가 결과를 포함한다. 기본 탭은 **개선 전후 비교**다. Linux/Python 3.11에서 앱과 단위·재현 검사를 실행했다. Windows 자체에서의 구동은 현장 확인 항목이다.

1. 첫 화면 **기존 2,000회 재시험 / 진폭 RF / E**에서 오류 415 → 233, 고친 오류 222, 새 오류 40을 확인한다. **고친 오류**와 **새 오류**를 번갈아 누르면 같은 입력의 저장 결과를 실제 모델로 재계산한다. E는 고립 피크만 보정한 뒤 기존 RF에 넣는다.
2. **전체 480구간 평가 / 진폭 + 주파수 RF / F**에서 원본·X축 충격·Y축 충격을 차례로 본다. F는 RF 대신 진동의 주파수 분포와 축 간 관계를 학습한 별도 분류기다. 같은 비교에서 G를 고르면 축·세기·위치 수를 분산해 학습한 결과를 볼 수 있다.
3. **자동 실패 탐색**에서 라이브 탐색 또는 저장 결과를 선택한다. 선택한 사례에서 **이 실패를 수정 후보로 다시 시험**을 열면 새로운 실패도 동일한 입력으로 시험한다. **보류 규칙을 같은 자동 처리량에서 비교**는 개선 전후 탭 아래에 있다.

## 무엇을 고쳤나

- 회귀 2,000회는 기존 진폭 RF가 원본을 맞힌 40개 창에 대한 선택된 시험이다. E의 잡음 시험 오류는 103/560 그대로였다. 스파이크 오류는 312/1,440 → 130/1,440으로 줄었다. 480개 전체 원본에서는 E의 집계 검출·오경보가 변하지 않았다. 이를 전체 조업 정확도 상승으로 해석할 수 없다.
- A~D는 두 RF 계열에서 원본/증강, 기존/강건 특징의 2×2 비교다. D의 진폭 RF는 기존 회귀에서 177건을 고치고 310건을 새로 틀렸다. D를 기본 분류기로 승격하지 않았다. 전체 주파수 RF에서는 B가 X축 충격 오경보를 192 → 108로 줄였지만 검출도 96 → 70으로 줄었다.
- 후속 후보 F는 512샘플 단위로 주파수 분포와 축 간 결합을 요약하고 로지스틱 회귀로 평가했다. X축 충격에서는 기존 주파수 RF보다 검출과 오경보가 모두 개선됐다. Y축 충격 오경보는 크게 증가했다. G는 훈련용 충격을 여러 축·세기·개수로 분산해 F의 Y축 취약성을 확인했다. 원본 원자료·합성 복사본의 라벨이 같다는 가정 아래의 결과다.

| 시험 / 전체 480구간 | 기존 주파수 RF · 검출/오경보 | F · 검출/오경보 | G · 검출/오경보 |
|---|---:|---:|---:|
| 원본 | 69 / 100 | 101 / 122 | 83 / 120 |
| 잡음 | 69 / 119 | 103 / 130 | 92 / 141 |
| X축 충격 | 96 / 192 | 104 / 111 | 85 / 106 |
| Y축 충격 | 75 / 87 | 138 / 245 | 85 / 122 |
| Z축 충격 | 58 / 85 | 14 / 12 | 91 / 132 |

검출 분모는 S 160개, 오경보 분모는 E/B 320개다. G와 기존 주파수 RF의 원본을 단순 오류 개수로 보면 기존 191개, G 197개다. S 검출 개선과 E/B 오경보 증가가 함께 있었다. X축에서의 개선을 모든 축·설비로 일반화할 수 없다. 동일한 16개 그룹에 대한 개발 비교이며, F·G는 앞선 결과를 보고 설계했다. 이 그룹을 보지 않은 독립 최종 시험은 아직 없다.

## 보류 규칙

기존 고정 G2 정책과 아티팩트는 보존했다. E(진폭 RF)와 G(다축 후보)에 대해, 각 바깥 훈련 fold의 12개 그룹 안에서 세 번의 그룹 분할을 수행했다. 내부 검증의 원본·잡음·충격 예측으로 (1) 점수의 경계 거리, (2) 오류 위험 추정(로지스틱 회귀)을 비교했다. E는 보정 전후 점수 차이, G는 다른 RF와의 점수 차이를 위험 특징으로 사용한다. 두 방식 모두 내부 결과를 이용해 목표 전달률 80%의 컷을 정하고 바깥 4개 그룹에서 측정했다. 별도로 각 평가 fold·조건에서 정답을 보지 않고 96/120을 골라, 두 정책이 정확히 같은 수의 판정을 전달할 때의 오류도 비교했다. 후자는 배치 검토 모드이며 단건 실시간 임계값을 뜻하지 않는다.

G 모델에서 정확히 384/480을 전달할 때 원본은 경계 거리 방식이 146건, 위험 추정이 151건의 오류를 전달했다. X축 충격은 각각 131건, 136건이다. Y축에서는 152건, 149건이다. 일관된 우위가 확인되지 않아 새 보류 규칙을 기본으로 적용하지 않았다.

## 실험 재실행 (가상환경 활성화 후)

    python -m pip install -r requirements.lock.txt
    python -m src.improve
    python -m src.impulse
    python -m src.shape
    python -m src.multi_axis
    python -m src.coverage
    python -m src.coverage G
    python -m unittest discover -s tests -v
    python -m streamlit run app.py

src/improve는 기존 v3 예측을 다시 만드는 대신 새 파일을 experiments/에 쓴다. 이 과정에서 새 RF의 훈련은 fold당 360개의 원본 또는 해당 원본의 훈련 전용 증강본을 포함한 1,080개로 제한한다. v3에서 발견한 2,000개 평가 교란본은 회귀 시험에만 사용한다. 입력 해시·모델 버전·fold 매핑은 v3 경로를 유지한다. 기존 결과는 reports/, 새 시험 점수·그룹 분할·정책 비교·학습 모델은 experiments/에 있다. 실험 순서 및 선택 기준은 experiments/PROTOCOL.md에 있다. 초기 계획에서 정한 D의 기준은 잠정 검토 조건이고, 기존 실패 재시험에서 새 실패가 더 많으면 전체 대체 후보로 권하지 않는다.
