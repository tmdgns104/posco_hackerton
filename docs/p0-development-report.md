# SteelTrust P0 개발 현황

## 구현된 항목

| 요구 | 현재 구현 |
| --- | --- |
| 이진 오류 전이 | 기존 저장 실행의 동일 원본·조건·seed에 대해 신규/해결/공통 FN, 공통 TP, 신규/해결/공통 FP, 공통 TN과 추론 실패를 분류한다. 실패 사례 화면에서 유형별 원본을 볼 수 있다. |
| 조건별 집계 | 기존 실행의 실제 조건·seed별 원본 수, 불량·정상 원본 수, 판정 수와 전이 건수를 표시·CSV 저장한다. |
| 주석 면적별 분석 | KSDD2의 원본 마스크 결함 픽셀 비율을 이용해 사용자 설정 구간별 FN 전이를 표시한다. 면적 구간은 현장 위험 기준이 아니다. |
| 신뢰한 로컬 모델 등록·평가 | K0/K1 호환 joblib 분류 헤드를 명시적 신뢰 확인 후 등록하고 해시를 기록한다. 동일 입력으로 기준 모델과 비교하며 등록 후보의 공식 시험은 허용하지 않는다. 등록 모델을 사례 재시험·재현에도 사용할 수 있다. 모델 학습은 제공하지 않는다. |
| 원본 픽셀 밝기 | 해시 확인된 원본 RGB의 평균 `0.2126R + 0.7152G + 0.0722B`를 구하고, 사용자 설정 구간의 원본·판정 수와 FN/FP 전이를 표시한다. 조도나 교란 후 밝기가 아니다. |
| 로컬 이벤트 기반 | UI에서 모델·데이터 등록, 평가, 사례 재시험 및 설계 스냅샷의 시작·완료·실패를 JSONL에 저장하고 조회한다. OS 계정은 인증되지 않으며 변조 방지·CLI 작업 기록은 제공하지 않는다. |
| 원본 단위 불확실성 | 원본 ID를 그룹으로 복원추출하고 모델 쌍과 반복 판정을 유지한다. 재현 가능한 seed, 반복 수, 유효 재표본 수, 점추정과 95% 백분위 구간을 제공한다. |
| 분모·가중 방식 | 원본 수와 판정 수를 구분하며, 전체 판정 동일 가중 또는 원본별 동일 가중을 선택한다. 해당 정답의 추론 실패 또는 0 분모는 비율을 N/A로 둔다. |
| 설계 스냅샷 | 검증 분할에 한해 가설·기준과 모델 identity·임계값, 데이터·규약·코드 해시 및 조건을 새 파일에 저장하고 현재 설정과 비교한다. 작성자는 사용자 입력이며 인증되지 않는다. |
| 분할 중복 점검 | 데이터 인덱스에 존재하는 원본 ID, 파일 해시, 그룹, 부모 ID, 설비 및 촬영 그룹 필드를 검사한다. 실제 제공되지 않은 필드는 검사하지 않는다. |
| 기존 기능 | 기존 모델·실행 기록·공식 시험 접근 잠금과 기존 교체 기준을 변경하지 않았다. |

기본 KSDD2 전체 검증 기록에서 원본은 466장, 판정은 3,262회이며 신규 FN 34회, 해결 FN 6회, 신규 FP 71회, 해결 FP 409회다. 이 수는 같은 원본에서 여러 조건을 반복한 **판정 횟수**이고 서로 독립된 3,262장이라는 뜻이 아니다.

## 실행 및 검증

Windows에서는 기존 `START_WINDOWS.cmd`를 사용한다. 또는 `SlagWatch`에서 Python 3.11 가상환경을 사용해 실행한다.

```text
python start_demo.py
python -m unittest tests.test_inspection_reliability tests.test_inspection_runner tests.test_inspection_projects -v
```

이 문서는 KSDD2를 포함한 P0 구현 기록이다. 현재 앱 화면은 NEU 강판 프로젝트만 표시하므로 KSDD2의 이진 전이·면적·Bootstrap 화면은 숨겨져 있으며 관련 코드와 기록은 남아 있다. NEU의 **전이·통계 분석**에서는 선택한 실행의 조건별 정확도·macro F1과 오분류 변화를 확인할 수 있다. **평가 설계 기록**은 `SlagWatch/inspection_governance/` 아래의 로컬 파일로 저장된다. 기록은 Git에서 기본 제외된다.

테스트는 합성 입력으로 8가지 전이, 반복 원본과 가중 방식, 분모 0과 추론 실패, 재현성, 분할 누수 및 동결 후 임계값 변경을 검증한다. 저장된 전체 검증 기록의 전이 건수도 별도로 확인한다.

## 제한 및 미구현

- 등록 모델은 신뢰한 로컬 joblib만 지원한다. 로드 시 임의 코드가 실행될 수 있고 해시는 안전성 검증이 아니다. 고정 인코더와 같은 전처리·분류기 구조만 지원하며 K2 학습이나 새 모델 결과 생성은 제공하지 않는다.
- 결함 형태, 대비 및 실제 촬영 조건별 메타데이터 분석과 히트맵은 미구현이다. 원본의 픽셀 밝기는 실제 조도가 아니며 물리적 원인을 추정하지 않는다. 면적별 표에는 정상 FP가 포함되지 않는다.
- 원본 ID 기준 Bootstrap은 제품·코일·설비·시간의 독립성을 보장하지 않는다. 유사 이미지나 관련 생산 단위가 여러 원본 ID로 포함되면 구간이 지나치게 좁을 수 있다. 조건별 해석에 유의하고 추가 외부 검증이 필요하다.
- 로컬 스냅샷은 **검증 설계 기록**이다. 새 실행을 해당 스냅샷에 강제 연결하지 않으며, 사전 등록 시점이나 작성자 신원을 인증하지 않는다. 해시는 우발적 변경 탐지용이고 파일과 해시를 함께 수정할 수 있는 사용자에 대한 보안 통제가 아니다. 이벤트 기록도 UI 작업만 대상으로 하며 인증·변조 방지, 열람 이력, 승인·거부 이력 및 접근 통제는 미구현이다.
- 기존 공식 시험 잠금은 바꾸지 않았다. 최종 시험에 대한 동결-실행 바인딩, 독립성 검증 및 PASS/FAIL/REVIEW/INVALID/NOT EVALUATED 통합 승인 엔진은 미구현이다. 기존 화면의 `기준 미달`은 개발 검증 기준 결과이며 최종 승인 결과가 아니다.
- 데이터 분할 중복 검사는 제공된 ID·해시·그룹 필드에 한정한다. 설비·시점 정보가 없다면 외부 독립성을 판단할 수 없으며, perceptual hash 검사는 구현하지 않았다.
- Confidence score는 기존 실행의 decision score를 사례 상세에서 확인할 수 있다. 보정된 확률로 해석하지 않는다. 객체 탐지, IoU 매칭 및 객체 단위 오류 분석은 미지원이다.
- 신뢰구간과 합성 교란 결과는 실제 사고 확률이나 현장 안전 인증이 아니다. 실제 운영 결정을 위해 별도 승인 절차와 독립 검증이 필요하다.
