# SteelTrust 프로젝트 개요와 개선 제안

## 1. 문서 목적

이 문서는 [제출 기획서](../../SteelTrust_제출_어떻게든하조.docx)와 현재 저장소의 구현·실험 문서를 함께 검토해 작성했다. 기획서의 **목표**와 현재 코드에서 확인한 **구현**을 구분하며, 미구현 사항을 이미 달성한 성과로 표현하지 않는다.

## 2. 프로젝트 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 목표 | AI 모델의 입력 변화에 따른 오류를 발견하고, 모델 교체 전후 결과를 비교·기록하는 검증 도구 |
| 대상 사용자 | 검사 AI 개발자, 품질 검증 담당자, 모델 교체 의사결정자 |
| 현재 중심 사례 | 동일한 산업 표면 이미지에 대한 정상·불량 검사 모델 K0/K1 비교 |
| 주요 기능 | 정답이 있는 이미지 등록, 동일 입력·조건의 추론, 오류 변화 분석, 사례 저장 및 재시험 |
| 기술 구성 | Python 3.11, Streamlit, PyTorch ResNet18 기반 특징 추출, scikit-learn 분류기 |
| 현재 판단 | K1은 오경보를 줄였지만 미검출이 늘어 사전 교체 기준에 미달 |
| 한계 | 공개 데이터와 합성 교란을 이용한 개발 검증이며, 실제 공정의 안전·생산 효과나 현장 인증은 입증하지 않음 |

**현재 화면 및 추가 기능:** 워크스페이스는 NEU 강판 결함 6종만 표시하며 KSDD2·슬래그 파일과 아래 실험 설명은 보존한다. 별도 표형 실험실에서 신뢰한 scikit-learn 분류 모델의 등록·동일 조건 비교·로컬 교체, sample_id 단위 짝 Bootstrap 및 보류 정책을 제공한다. 이미지와 표형은 공통 어댑터 계약을 제공하지만 실행기가 하나로 합쳐진 것은 아니다. 모델 변경에는 로컬 계정 권한과 임시 로컬 감사 기록이 필요하다. 임시 감사 저장소는 외부 독립 저장소나 운영용 변조 방지가 아니며 NEU 신규 모델 등록·교체, 공식 승인과 설비 배포는 제공하지 않는다. 사용법과 범위는 [앱 README](../SlagWatch/README.md)를 따른다.

SteelTrust는 모델의 평상시 정확도만 보는 대신, 입력 조건과 모델 버전이 바뀌었을 때 **기존에 맞히던 사례를 새로 틀리는지**를 확인한다. 오경보와 미검출을 분리해 개선과 악화를 함께 보여 주고, 실패 입력을 보관해 후속 모델의 회귀시험에 활용한다.

## 3. 기획서의 문제와 목표

기획서는 철강 현장의 영상·센서·공정 AI가 잡음, 입력 누락, 이상치 등으로 흔들릴 수 있으며, 팀마다 검증 방법이 다르면 모델 비교와 실패 재현이 어려워질 수 있다는 문제를 제기한다. 제안한 해법은 모델과 데이터를 공통 계약으로 연결하고, 동일 조건의 교란·추론·평가·사례 재현을 반복하는 것이다.

기획서의 목표 흐름은 다음과 같다.

1. 모델과 데이터 등록 및 입력 계약 확인
2. 교란 조건·강도·시드 설정
3. 원본과 교란 입력에 대한 추론
4. 오류 및 PASS/HOLD 정책 평가
5. 실패 사례 비교·재현 및 결과 내보내기

기획서의 최초 MVP는 **숫자형 표 데이터의 서로 다른 분류 모델 두 개**를 공통 인터페이스로 시험하는 것이었다. 영상과 진동 시계열은 후속 확장으로 구분했다. PASS/HOLD는 자동 전달과 사람의 추가 검토를 비교하기 위한 시연 정책이지, 설비 제어 명령이나 안전 인증이 아니다.

## 4. 현재 구현과 기획의 차이

| 구분 | 기획서 목표 | 현재 저장소에서 확인한 내용 |
| --- | --- | --- |
| 주 평가 대상 | 숫자형 표 데이터부터 시작하는 범용 분류 모델 | KSDD2 정상·불량 및 NEU-CLS 결함 6종의 이미지 검증이 중심 |
| 모델 연결 | 서로 다른 모델을 공통 어댑터로 교체 | 공통 이미지 실행기와 등록된 K0/K1, V0/G1 어댑터가 있음. 임의 모델을 자유롭게 업로드하는 범용 등록 기능은 아님 |
| 데이터 연결 | 데이터·피처·클래스 계약을 명시적으로 검증 | 정답 CSV와 이미지 ZIP 또는 폴더를 등록. 기존 이미지 검사 템플릿과 클래스 체계를 사용 |
| 시험 조건 | 노이즈·이상치·누락·값 고정 등 공통 시나리오 | 이미지 사례에서 원본·잡음·밝기 변화를 비교. 슬래그 시계열의 별도 이전 실험도 보존 |
| 평가·재현 | 오류, 보류와 커버리지 비교 및 실패 재현 | 이미지 모델의 오분류 변화, 사례 저장·재시험과 결과 기록이 중심. PASS/HOLD 실험은 이전 슬래그 경로의 별도 기록이며 이미지 교체 판단에 공통 적용된 것으로 볼 수 없음 |
| 결과 제공 | 대시보드와 CSV/JSON/PDF 또는 DOCX 보고서 | Streamlit 화면, 저장된 실행 결과와 사례 ZIP·CSV 제공. 통합 PDF/DOCX 보고서 생성은 기획 목표로 취급 |

현재 구현은 기획의 모델 독립성 가설을 **이미지 검사 도메인에서 부분적으로 구체화한 사례**다. 숫자형 표·영상·시계열을 동일한 범용 계약으로 모두 지원한다고 단정할 수는 없다.

## 5. 현재 사용 흐름과 구성

### 사용 흐름

1. **프로젝트 선택**: 현재 화면에서는 NEU-CLS 6종 분류와 NEU 템플릿으로 등록한 프로젝트를 선택한다. KSDD2는 코드와 기록만 보존한다.
2. **교체 판단**: 기존 전체 검증 기록과 후보 모델의 채택 여부를 확인한다.
3. **새 검증 실행**: 동일 이미지와 시험 조건을 두 모델에 적용한다. 부분집합 실행과 전체 검증을 구분한다.
4. **실패 사례 분석**: 고친 오류와 새로 발생한 오류를 원본·조건별로 확인한다.
5. **저장 및 재시험**: 사례를 저장하고 기존 입력과 모델 버전을 이용해 재현하거나 다른 등록 모델을 재시험한다.
6. **새 이미지 등록**: 정답이 포함된 CSV와 이미지로 개발용 프로젝트를 만든다. 정답 없는 자료로 성능을 평가하지 않는다.

## 6. 검증 데이터와 측정 결과

### KSDD2 정상·불량 검사

KolektorSDD2의 공식 학습 범위에서 개발 학습 1,865장과 검증 466장(불량 49장, 정상 417장)을 분리했다. 검증 원본마다 원본·잡음·밝기 변화 총 7조건을 적용해 **3,262쌍의 판정**을 비교했다. 3,262는 독립된 원본 장수가 아니라 같은 원본을 반복한 조건별 판정 수다.

| 범위 | 지표 | K0 | K1 |
| --- | --- | ---: | ---: |
| 원본 466장 | 불량 재현율 | 85.71% (42/49) | 79.59% (39/49) |
| 원본 466장 | 정상 오경보율 | 7.91% (33/417) | 7.19% (30/417) |
| 7조건 3,262회 | 불량 미검출 | 48회 | 76회 |
| 7조건 3,262회 | 정상 오경보 | 601회 | 263회 |

동일 입력의 짝 비교에서 고친 미검출은 6회, 새 미검출은 34회, 해소한 오경보는 409회, 새 오경보는 71회다. K1은 오경보를 줄였지만 미검출이 증가했고 조건별 사전 기준도 충족하지 못해 **교체 후보로 채택하지 않았다**. 공식 시험 분할의 성능 평가는 열지 않았다. 상세 조건과 사례는 [KSDD2 검증 결과](../SlagWatch/experiments/inspection_binary/VALIDATION_FINDINGS_KO.md)를 참고한다.

### 이전 사례

- **NEU-CLS**: 공개 강판 결함 6종 분류에서 기존 V0와 잡음 학습 후보 G1을 비교한다. 정상 제품 검출이나 새로운 공장의 일반화 성능을 의미하지 않는다.
- **SSFD 슬래그 진동**: 시계열 교란·모델 비교·보류 정책의 이전 실험 기록이다. 기획의 범용 확장 가능성을 보여 주는 별도 사례이며, 실제 안전사고 발생률을 측정한 자료가 아니다.

## 7. 우선순위별 개선 제안

아래는 제안이며 현재 구현되었다는 뜻이 아니다. 실제 적용 전 데이터 이용 조건과 평가 규약을 확정해야 한다.

### P0. 모델 교체 판단의 신뢰성 강화

1. **새 미검출 중심의 후속 후보 설계**: K1이 새로 놓친 원본의 결함 크기·형태·밝기 조건을 개발 데이터에서 분류하고, 이를 근거로 후보 변경 가설을 사전에 기록한다. 기준과 평가 데이터를 사후에 바꾸지 않는다.
   - 완료 기준: 변경 가설, 조건별 FN/FP, 새로 생긴 오류와 해결한 오류를 같은 표에 기록하고 기존 사전 기준의 충족 여부를 표시한다.
2. **평가 단위와 불확실성 표시**: 원본 수와 반복 판정 수를 항상 함께 표시하고, 원본 단위 그룹을 기준으로 신뢰구간 등 불확실성을 별도 분석한다.
   - 완료 기준: 466장과 3,262회를 혼동하지 않도록 화면·보고서에 분모를 명시하고, 조건별 결과와 불확실성 산출 방법을 공개한다.
3. **독립 최종 검증 유지**: 개발 사례를 반복해서 활용한 뒤에는 새 설비·촬영 시점 또는 공장 단위로 분리한 데이터에서 최종 확인한다. 현행 공식 시험 잠금을 우회하지 않는다.
   - 완료 기준: 최종 평가 전 분할·가설·임계값을 동결하고, 접근 이력과 분할 간 중복 검사를 남긴다.

### P1. 범용 플랫폼 목표와 현재 제품의 간극 축소

4. **공통 계약의 명시적 확장**: 이미지 실행기의 장점을 유지하면서 입력 스키마, 모델 ID, 클래스·점수 유형, 실패 상태를 문서화하고 숫자형 표 모델용 어댑터를 별도로 추가한다.
   - 완료 기준: 서로 다른 표 분류 모델 두 개를 같은 데이터·시드로 평가하고 피처 누락, 순서 오류, 클래스 불일치에 명시적으로 실패한다.
5. **보류 정책을 별도 실험으로 연결**: 이미지 검사에서도 자동 전달률과 오판 전달·불필요한 보류를 함께 계산하는 실험을 설계한다. 현재 교체 판단 결과와 혼합하거나 안전 확률로 표현하지 않는다.
   - 완료 기준: 정책·임계값을 사전 고정하고 동일 커버리지 비교, 미검출·오경보 및 0 분모 처리를 테스트한다.
6. **보고서와 추적성 강화**: 데이터·모델·코드 해시, 시험 조건·시드, 실패 건수와 미완료 건수, 분모 및 한계를 한 보고서에 묶는다.
   - 완료 기준: 동일 실행 ID에서 CSV/JSON 요약과 사람이 읽는 보고서를 생성하고, 실패 실행을 성공과 구분한다.
--
### P2. 운영 및 현장 적용 준비

7. **현실적인 교란과 외부 데이터 확보**: 실제 카메라·조명·설비 변동의 범위와 빈도를 현장 담당자와 정의하고, 합성 조건과 실측 조건을 구분한다.
8. **배포·운영 안정화**: Windows 클린 설치와 오프라인 재실행을 자동 검증하고, 대용량 데이터와 모델의 무결성·버전·저장 위치를 관리한다.
9. **현장 비용 및 데이터 권리 검토**: 작업자 검토 시간, 재검사 비용, 미검출 영향은 별도 실측 계획을 세운다. KSDD2는 CC BY-NC-SA 4.0이며 NEU 재배포·상업적 이용 조건은 별도 확인이 필요하다.

## 8. 해석과 사용 시 주의

- 합성 잡음·밝기 변화는 시험 조건이지 실제 현장의 발생 빈도나 사고 위험을 뜻하지 않는다.
- 조건별 반복 판정을 독립된 원본 표본 수로 해석하지 않는다.
- 모델 점수와 PASS/HOLD 결과를 안전 확률, 실제 사고 감소율 또는 생산 가동률로 표시하지 않는다.
- 이 도구는 실설비 제어, 안전 인증 또는 사람의 최종 판단을 대체하지 않는다.
- 데이터 라이선스와 실제 업무 적용 권한을 데이터별로 별도 확인한다.
